# Unified auth promotion reads and role-aware Google callback routing

The change makes both public authentication surfaces read the same active promotion, with a safe Vowza fallback when the record, image, or request is unavailable. The admin replacement path uploads a new object, commits its database reference, then removes the old object; failed persistence attempts clean up the newly uploaded object instead. Google sign-in now has a public entry point and the callback waits for roles before choosing admin, provider, or customer destinations, while protected-action returns retain priority. The tracked local diff also bundles face-liveness, provider-registration, booking/OTP, and document-verification work that is unrelated to this auth change. Watch for: **confirmed, non-blocking** the new anonymous promotion reader fetches internal configuration fields unnecessarily; **confirmed, non-blocking** these auth flows have no automated coverage; and **confirmed, non-blocking** the mixed diff broadens review and release risk.

**Verdict**: APPROVED

## High-level view

Public auth pages and the authentication modal now share one refreshable active-promotion source. Its empty-on-refresh behavior prevents a superseded, hidden, missing, or unreadable image from surviving, and each surface falls back to its built-in Vowza panel.

Promotion replacement is sequenced to keep the last valid database reference live until the new image has persisted. Deleting or hiding a promotion similarly updates the configuration before doing best-effort object cleanup, so storage failure leaves an orphan rather than a broken public panel.

Google OAuth returns through the existing callback route, which holds until the role lookup completes. It sends admins and super-admins to `/admin/dashboard`, providers to `/vendor/dashboard`, and customers home; a saved protected action continues to win over these defaults.

The public reader now receives more configuration data than it needs, and no tests exercise public fallback, OAuth return handling, role destinations, or storage/database failure ordering. The working tree also combines independent product work with this auth-focused change.

<summary>Details</summary>

### Public promotion fallback and the storage-to-database handoff

`useAuthPromotion` is now the common public source for `/auth` and `AuthModal`. It clears the prior promotion before every fetch and on a disabled modal, while both rendering surfaces drop a bad image on `onError`; an unavailable query, missing active row, or failed object therefore resolves to the built-in panel rather than retaining stale promotional content. The event notification refreshes mounted surfaces in the same browser context after a successful admin mutation; fresh auth visits independently fetch the current active record.

The replacement sequence in `AdminAuthPromotionalManager` validates and uploads the new image, stores that new URL and path in the configuration, and only then deletes the old object. If the database write fails, it attempts to remove the new object and retains the old database pointer. On deletion, the configuration is first cleared and then the old object is removed, so a storage failure leaves an orphaned object but never a row that points at a removed image.

### Role-aware callback preserves the protected action

The public Google action delegates to the existing OAuth call with `/auth/callback` as the return URL. `AuthCallback` now waits for `rolesLoaded` once a session exists, preventing the customer fallback from firing while roles are still in flight. Its destination logic matches the direct password-sign-in page: `admin` and `super_admin` go to the admin dashboard, `provider` goes to the vendor dashboard, and every other resolved role goes home.

The callback still checks `hasReturnTo` before selecting a default destination. `useAuthRedirect` registers its authenticated-user effect first, clears the saved action before navigating, and the callback consequently does not replace a protected booking or checkout continuation with a dashboard redirect. An unsuccessful OAuth return continues to fail closed to `/auth`.

### Public configuration metadata is broader than the rendering contract

**Confirmed, non-blocking:** `fetchAuthPromoConfig` is called before authentication by both auth surfaces, but `fetchPromoConfig` uses `select('*')`. The table policy allows anonymous reads, so those requests now return `admin_id` and `image_storage_path` even though the page only renders `current_image_url`, `overlay_opacity`, and `overlay_color`. The bucket is intentionally public and these fields are not credentials, but returning ownership and internal object-path metadata expands the anonymous contract without a rendering need. Restrict the public query to those three fields (or expose a narrowly shaped public view) while leaving the full-row admin reader intact.

### Coverage is absent for the changed trust and failure boundaries

**Confirmed, non-blocking:** no matching automated tests were found for `useAuthPromotion`, the admin promotion manager, Google sign-in, or `AuthCallback`. The production build passes, but it cannot prove that anonymous query failures show a fallback, that a replacement database failure cleans up the uploaded object without losing the current image, or that callback timing retains a protected action and selects the correct role destination. Add focused component/service tests with mocked Supabase responses for these boundaries.

### Face verification and booking work are outside this change’s boundary

**Confirmed, non-blocking:** this local diff includes a large face-liveness rewrite and `face-api.js`, provider-registration gating, document-verification changes, booking execution changes, vendor booking updates, and removal of `send-booking-otp`. Those behaviors are unrelated to promotion synchronization or Google callback routing, making it materially harder to validate and revert the auth change in isolation. Move them to separate commits or review units; the untracked service-start OTP functions and migrations should be included with that separate work rather than this auth review.
