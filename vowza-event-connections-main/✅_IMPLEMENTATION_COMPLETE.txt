═══════════════════════════════════════════════════════════════════════════════
  HOW IT WORKS
═══════════════════════════════════════════════════════════════════════════════

WHEN ARTIST TRIES TO BOOK:

  Database checks:
    1. Is customer_id = auth.uid() ?
       (User booking for themselves)
    2. Is there a provider_profiles record where:
       - id = package's provider_id AND
       - user_id = auth.uid()
       (User owns the vendor)

  If both checks pass:
    → Booking ALLOWED ✓

  If either check fails:
    → Booking BLOCKED ✗
    → Error: "new row violates row-level security policy"
